# 部门目标关联待办与待办产物设计

## 目标

将部门指标的实际贡献统一来源于具体待办：待办可关联一个或多个指标并填写贡献数，只有待办完成后贡献才计入指标。产物归属于待办，目标页仅提供只读的关联待办与产物查看入口。

## 已选方案

采用“待办为唯一事实源”的方案。继续使用待办现有 `goalLinks` 保存指标关联和贡献信息，不新增独立关联表。目标页的关联待办、贡献汇总和产物信息均由待办数据派生。

## 范围

- 调整部门目标表的列、顶部操作和删除交互。
- 新增只读的“关联待办事项详情”。
- 关联指标、贡献数及说明只能在待办详情中新增或变更。
- 指标完成值只累计状态为“已完成”的关联待办贡献数。
- 产物从目标迁移为待办能力，每个待办最多保留一个当前产物。
- 删除旧目标产物入口、接口和目标上的产物元数据逻辑。
- 当前环境没有历史目标产物，不执行文件迁移；旧目标产物字段按废弃数据处理。

## 非目标

- 不新增独立的指标与待办关联实体。
- 不在目标页编辑待办、贡献或产物。
- 不支持单个待办的多个产物、产物版本历史或在线编辑。
- 不删除与目标解除关联的待办。
- 不顺带重构目标或待办页面的其他功能。

## 页面与交互

### 部门目标页

1. 删除“产物”列。
2. 将“操作”列改名为“关联待办”。
3. 每行只显示查看关联待办的入口，不显示拆解或删除按钮。
4. 删除顶部“恢复初始目标”按钮。
5. 在“新增目标”旁增加“删除目标”按钮。
6. 点击“删除目标”后进入选择态，目标表显示选择框，并提供“确认删除”和“取消”。支持单选与批量选择。
7. 未选中任何目标时不能确认删除；确认前明确显示选中数量并二次确认。
8. 删除目标后，从所有待办的 `goalLinks` 中清除对应关联，但保留待办本身。

### 关联待办事项详情

点击目标行的“关联待办”入口打开只读详情，展示：

- 待办标题、负责人、所属模块和状态；
- 对当前指标填写的贡献数、单位及贡献说明；
- 当前贡献是否已计入指标；
- 待办产物的文件名、更新时间、查看和下载入口；
- 进入该待办详情的入口。

该页面不提供新增关联、解除关联、修改贡献或管理产物的操作。所有变更必须进入待办详情完成。没有关联待办时展示明确空状态。

### 待办详情

- 沿用现有指标选择能力，允许一个待办关联多个指标，并分别填写贡献数、单位和说明。
- 新增待办产物区域：无产物时可上传，有产物时可预览、下载、替换或删除。
- 每个待办最多一个当前产物，新上传成功后替换旧产物。
- 产物支持的文件类型、20 MB 上限、预览转换及安全规则沿用现有目标产物能力。

## 数据与计算规则

### 指标关联

待办 `goalLinks` 是关联关系的唯一事实源。每条关联至少包含：

- `goalId`
- `contribution`
- `unit`
- `note`

保存待办时继续兼容现有单关联字段，但读取、展示和汇总均以规范化后的 `goalLinks` 为准。

### 贡献汇总

某指标的实际完成值等于所有满足以下条件的待办贡献数之和：

1. `goalLinks` 中关联该指标；
2. 待办当前状态为“已完成”；
3. 贡献数为有效非负数。

未完成待办只显示关联关系，计入贡献为 0。待办变为已完成时立即纳入汇总；从已完成改为其他状态时立即移出汇总。目标页不再允许直接编辑派生出的实际完成值。

### 待办产物

产物安全元数据挂在待办上，字段结构沿用现有产物能力，包括原文件名、MIME、大小、存储键、预览信息、更新时间和更新人。客户端普通待办保存不得覆盖服务端维护的产物元数据。

## API 与服务边界

- 将目标产物服务调整为待办产物服务，路由资源从目标 ID 改为待办 ID。
- 上传、预览、下载和删除都必须校验登录用户、部门边界、待办存在性和操作权限。
- 预览与下载权限跟随待办查看权限；上传、替换和删除权限跟随待办编辑权限。
- 上传替换继续使用事务顺序：先写新文件，再保存待办元数据，成功后清理旧文件；失败时保留旧产物。
- 删除目标接口需在同一次受控保存中清除所有待办里的对应 `goalLinks`，避免留下悬空关联。

## 旧能力清理

- 删除目标表产物列、目标产物弹窗和相关事件处理。
- 删除目标产物 API 路由及目标专属服务命名和调用。
- 目标响应不再暴露或维护 `artifact` 字段。
- 当前没有历史产物文件，因此不提供迁移脚本；已有旧目标 `artifact` 元数据读取时忽略，并在后续目标保存时不再保留。

## 错误处理

- 关联待办加载失败时保留目标页，详情中显示重试提示。
- 批量删除部分保存失败时不得展示为全部成功；保持可重试状态并刷新服务端真实数据。
- 待办产物格式、MIME、大小、转换或权限错误沿用现有明确提示。
- 产物缺失或损坏不影响待办详情和关联待办列表加载，只将该产物标记为暂不可用。
- 删除目标时即使存在关联待办也允许删除，但必须在确认文案中说明会解除多少条待办关联。

## 验收标准

1. 目标表不再出现产物、拆解、行内删除和恢复初始目标入口。
2. 顶部删除目标支持进入选择态、单选、批量选择、取消和二次确认。
3. 删除目标只解除对应待办关联，不删除待办，不留下悬空 `goalLinks`。
4. 关联待办事项详情只读，并能进入具体待办详情。
5. 关联和贡献只能在待办详情新增或变更。
6. 未完成待办贡献为 0；完成后计入；撤销完成后移出；多个完成待办正确累加。
7. 待办产物可上传、替换、预览、下载和删除，并遵守权限及文件安全限制。
8. 关联待办事项详情可查看每个待办的产物信息和预览/下载入口，但不能管理产物。
9. 无产物、无关联待办、文件损坏和无权限场景均有明确且不阻断页面的反馈。

## 验证策略

### 自动验证

- 领域测试：完成状态过滤、多待办累加、撤销完成、无效贡献数和多指标关联。
- API 测试：待办产物上传、替换回滚、预览、下载、删除、跨部门与无权限访问。
- 删除测试：单个和批量删除、关联清理、保存失败及无悬空关联。
- UI 合约测试：目标表列与按钮、选择态、只读关联详情、待办产物入口及状态变化后的汇总刷新。

### 手工验证

- 从目标进入关联待办详情，再进入待办详情修改关联，返回后确认数据刷新。
- 分别用未完成、已完成和撤销完成状态验证贡献变化。
- 使用真实图片、PDF 和 Office 文件验证待办产物预览、替换和下载。
- 选择一个及多个目标验证取消、确认提示和删除后的待办保留情况。

## 预计修改范围

- `PRD.MD`：同步确认后的产品行为。
- `public/index.html`：目标表、批量删除、只读关联详情、待办详情产物入口和贡献展示。
- `api/[...path].mjs`：待办产物路由、目标批量删除及关联清理。
- `lib/goal-artifact-*` 或替代的待办产物服务模块：将资源归属从目标改为待办。
- `lib/task-core.mjs` 及相关测试：完成态贡献计算和服务端字段保护。
- `test/*`：补充针对性领域、API 和 UI 合约验证。

- `PROJECT_ARCHITECTURE.md`：将目标产物模块映射更新为待办产物模块映射。
