# 报告自动归档手动补跑设计

## 背景

周报、月报和季报已由后台定时任务自动归档，但外部调度或运行环境异常时仍可能漏跑。后台需要提供人工补偿入口，让全局管理员重新执行同一套到期检查，同时避免提前归档仍在编辑的报告。

## 目标与非目标

### 目标

- 在现有“后台 → 定时任务”列表新增“报告自动归档”任务卡。
- 允许全局管理员手动补跑已经到归档时间但仍未归档的报告。
- 自动执行与人工补跑共用同一套到期、归档和幂等逻辑。
- 展示最近执行状态、执行时间、触发方式、归档数量和简短失败原因。

### 非目标

- 不允许提前强制归档尚未到期的报告。
- 不增加按周报、月报、季报分别补跑的按钮。
- 不自动生成缺失报告，不补写或改写报告内容。
- 不在本功能中排查或重构外部调度平台。

## 交互设计

“报告自动归档”与现有“周任务结转”并列显示。任务卡展示：

- 任务名称；
- 周报、月报、季报当前配置的归档时间；
- 最近状态：从未执行、执行中、成功或失败；
- 最近执行时间和触发方式；
- 最近归档数量或简短错误信息；
- “立即补跑”按钮。

点击“立即补跑”时弹出确认：

> 确认立即补跑报告自动归档？只会归档已经到期的报告，不会提前归档仍在编辑的报告。

执行期间按钮禁用。成功后刷新任务卡并提示本次归档数量；没有符合条件的报告时明确提示归档 0 份，而不是报错。失败时展示稳定的用户提示，并保留任务状态供管理员再次补跑。

## 权限与接口

- 仅全局管理员可读取和运行报告自动归档任务。
- 部门负责人继续被 `scheduled-tasks` 管理接口拒绝。
- 在现有接口族中新增：`POST /api/admin/scheduled-tasks/report-auto-archive/run`。
- `GET /api/admin/scheduled-tasks` 同时返回周任务结转与报告自动归档两张任务卡的数据。

人工执行调用现有报告归档领域函数，`trigger` 记录为 `manual:<管理员用户名>`。接口返回更新后的任务摘要与执行结果。

## 数据与幂等

补跑使用当前服务器时间和后台归档配置判断到期：

- 周报仅在对应周日配置时间之后归档；
- 月报仅在对应月最后一天配置时间之后归档；
- 季报仅在对应季度最后一天配置时间之后归档。

仅处理 `draft` 或 `editing` 状态报告。已经是 `final` 的报告被跳过，因此同一时刻重复补跑不会重复归档。补跑不创建报告，也不修改报告正文。

执行状态持久化在现有状态文档中，至少保留最近一次运行的状态、开始时间、完成时间、触发方式、归档数量和截断后的错误信息。生成归档结果的函数不自行批准结果；API 在保存后返回持久化状态，测试通过重新读取验证结果。

## 错误处理

- 执行开始前先写入 `running` 状态。
- 成功后写入 `success` 和归档数量。
- 失败后写入 `failed` 与长度受限的错误摘要，再向调用方返回失败。
- 不自动连续重试；管理员可根据任务卡状态再次补跑。
- 进程重启后若发现长期停留在 `running`，任务摘要将其显示为异常或失败，而不是继续显示执行中。

## 验收与测试

1. 全局管理员能看到两类定时任务，部门负责人不能访问。
2. 手动补跑只归档已经到期的周报、月报和季报。
3. 未到期报告保持可编辑，缺失报告不会被创建。
4. 同一批报告重复补跑时，第二次归档数量为 0。
5. 成功、失败和从未执行状态均能在后台正确展示。
6. 确认文案明确说明不会提前归档。
7. 接口返回后重新读取持久化状态，与页面展示一致。
8. 现有自动归档、周任务结转和报告来源逻辑无回归。

## 预计修改范围

- `PRD.MD`：同步人工补跑的产品规则。
- `lib/report-auto-archive.mjs`：增加执行状态摘要或相邻的独立状态辅助逻辑。
- `api/[...path].mjs`：增加管理员补跑接口和任务列表摘要。
- `public/index.html`：展示任务卡、确认与结果反馈。
- `test/`：增加领域、API 和 UI 针对性测试。
