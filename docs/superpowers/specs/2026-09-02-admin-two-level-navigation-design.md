# 后台管理两级导航与页面合并设计

## 目标

将后台管理从单层左侧菜单重组为“顶部一级导航 + 左侧二级导航”，同时合并相关页面，降低菜单理解成本。保持现有后台权限、数据接口和高风险操作边界不变。

## 信息架构

| 一级导航 | 二级导航 | 合并后的内容 |
| --- | --- | --- |
| 组织管理 | 部门管理 | 部门基础信息、负责人、启停状态、工作模块 |
| 组织管理 | 成员管理 | 成员账号、所属部门、角色、负责模块、启停、密码重置 |
| 规则配置 | 保持登录 | 普通用户登录保持时长 |
| 规则配置 | 归档设置 | 周报、月报、季报自动归档时间 |
| 系统运维 | API 密钥 | AI 供应商、模型、启停、密钥状态、测试和清除 |
| 系统运维 | 定时任务 | 任务状态、最近执行结果、刷新和人工补跑 |

默认进入“组织管理 > 部门管理”。切换一级导航时，进入该组上次访问的二级页面；首次进入时选择该组第一项。

## 角色与权限

### 全局管理员

显示全部三个一级导航和六个二级页面，权限沿用现有后台能力。

### 部门负责人

只显示“组织管理”，二级导航为“部门管理、成员管理”。

- 部门管理：部门基础信息只读，可查看、增删改本部门工作模块。
- 成员管理：只管理本部门成员的角色、负责模块、启停状态和密码重置。
- 不新增或删除成员账号，不显示规则配置和系统运维。

导航隐藏仅用于界面精简，服务端权限仍是最终边界。

## 页面结构

### 部门管理

全局管理员可管理部门基础信息、负责人和启停状态，并在同一页维护选中部门的工作模块。部门负责人只看到本部门信息和可编辑的工作模块区域。

### 成员管理

全局管理员可按部门查看成员，并维护账号、角色和负责模块。部门负责人固定在本部门范围内，保留现有可编辑字段，不扩大账号创建和删除权限。

### 规则配置

“保持登录”仅承载登录保持时长。“归档设置”从原登录策略页面拆出，独立维护周、月、季归档时间，避免安全设置与业务归档混杂。

### 系统运维

“API 密钥”由原 AI 服务页面改名，保留供应商、模型、功能启停、密钥状态、测试连接和清除密钥。“定时任务”保留状态、结果、刷新和人工补跑能力。

## 导航与状态

- 桌面端：一级导航位于后台标题下方，二级导航位于内容区左侧。
- 窄屏端：一级和二级导航均变为可横向滚动的导航条，内容区保持单列。
- 一级、二级均提供明确选中态和无障碍当前项状态。
- 每个二级页面独立保存配置；测试连接、清除密钥和人工补跑使用独立按钮。
- 页面存在未保存修改时，对应二级菜单显示提示点。切换页面保留草稿；保存失败保留内容并显示原因。
- 清除密钥和人工补跑继续要求二次确认。

## 实现边界

主要修改 `public/index.html` 中的后台导航结构、样式、页面分组、活动状态和角色渲染逻辑；同步更新 `test/workbench-ui.test.mjs` 的后台导航、权限和控件映射断言。编码前先把确认后的产品行为同步到 `PRD.MD`。

不修改后台 API、权限策略、数据结构、密钥存储方式、定时任务执行逻辑，也不进行无关样式重构。

## 验收标准

1. 全局管理员看到三个一级导航及其六个二级页面，默认落在“组织管理 > 部门管理”。
2. 一级切换后展示对应二级导航，并记住各组最后访问项。
3. 部门管理包含工作模块，成员管理包含角色和负责模块管理。
4. 登录保持与归档设置分离；API 密钥与定时任务归入系统运维。
5. 部门负责人只看到组织管理，可编辑本部门工作模块和现有成员管理字段，不能新增或删除账号。
6. 未保存提示、切换保留草稿、失败保留内容及危险操作确认均有效。
7. 窄屏下两级导航可横向操作，内容不被固定左栏挤压。
8. 现有密钥安全控件、定时任务操作和后台权限测试继续通过。

## 风险与验证

后台结构、状态和角色逻辑集中在单页文件，主要风险是导航重组后面板映射或角色可见性错误。验证采用定向 UI 测试、内联脚本校验和桌面/窄屏人工检查；不运行与该功能无关的全量验证。
