# 部门待办四象限模式设计

## 目标

在现有部门待办页新增“四象限模式”，按照任务优先级展示重要紧急、重要不紧急、不重要紧急、不重要不紧急四类任务，同时完整保留现有列表看板模式。

## 已确认范围

- 首次进入部门待办默认使用四象限模式，并记住用户最后选择的模式。
- 四象限只展示未完成任务；已完成任务继续出现在列表模式和历史任务中。
- 任务卡跨象限拖动时同步修改优先级，不改变任务状态。
- 中心点可横向和纵向拖动，调整四块区域大小；布局按登录用户和部门保存在浏览器中。
- 提供“恢复默认布局”，将横纵比例恢复为 50% × 50%。
- 搜索、模块筛选、“只看我的”和批量管理同时适用于两种模式。
- 每个象限提供新增任务入口，新任务状态默认为“待开始”，优先级默认为当前象限。

## 方案选择

采用客户端双视图方案。现有状态看板继续由列表模式使用，新增独立四象限渲染函数；两种视图复用任务卡内容、筛选状态和现有任务 API。

不改动任务数据结构和后端接口，因为任务的 `priority` 字段已经支持四种目标值。布局和视图偏好属于界面状态，仅保存在客户端，不进入业务数据。

## 界面结构

### 模式切换

在部门待办工具栏加入“四象限模式 / 列表模式”分段按钮。首次默认四象限模式，后续读取当前用户最后一次选择。

### 四象限

四个区域的固定语义和视觉色为：

1. 重要紧急：红色，提示“立即处理，优先级最高”；
2. 重要不紧急：黄色，提示“重要但不紧急，规划时间处理”；
3. 不重要紧急：蓝色，提示“紧急但不重要，尽量授权或快速处理”；
4. 不重要不紧急：绿色，提示“不重要不紧急，有空再做”。

象限标题显示经过当前搜索和筛选后的未完成任务数量。没有任务时显示空状态，但仍保留新增任务入口和可接收拖入的区域。

### 中心点

中心点同时控制水平和垂直分割比例。拖动过程实时更新 CSS 自定义属性，比例限制在 25%–75%，避免任一区域不可用；松手后保存布局。

中心点可获得键盘焦点，方向键每次调整 1%，按住 Shift 时每次调整 5%。屏幕宽度不足时四个象限改为纵向排列并隐藏中心点，避免窄屏拖动失效。

## 任务交互

### 跨象限拖动

拖动开始时沿用任务卡现有拖拽数据。四象限的放置目标使用优先级标识，与列表模式的状态放置目标相互独立。

放下任务后：

1. 保存旧优先级；
2. 在本地更新为目标象限并重新渲染；
3. 立即调用现有任务保存接口；
4. 保存成功后显示同步成功；
5. 保存失败时恢复旧优先级、重新渲染并显示“分类更新失败”。

跨象限拖动不修改状态、截止日期、负责人或其他任务字段。

### 新增任务

点击象限内“添加任务”复用现有新增流程，请求中预填当前象限优先级和“待开始”状态。创建成功后任务直接出现在该象限，并打开或选中现有任务详情。

### 批量管理

批量选择、取消和删除沿用现有状态集合。删除后重新渲染当前模式并更新象限数量；本功能不增加批量修改优先级。

## 本地偏好

视图模式和布局使用登录用户名与部门标识组成存储键，避免同一浏览器上的不同用户或部门互相覆盖。读取到非法比例时回退到 50%，读取到未知模式时回退到四象限模式。

## 数据与兼容性

- 现有 `priority` 四种中文值直接作为象限键。
- 旧的 `P0`–`P3` 值继续通过现有标准化逻辑转换。
- 已完成任务的数据和状态不变，只在四象限渲染时排除。
- 列表模式维持当前按状态分列、跨列修改状态及阻塞原因校验等行为。
- 后端 API、持久化结构和部署适配层不变。

## 修改范围

- `PRD.MD`：补充四象限模式的已确认产品行为和验收标准。
- `public/index.html`：新增模式切换、四象限样式与渲染、中心点交互、偏好持久化及优先级拖放。
- `test/workbench-ui.test.mjs`：验证模式入口、四象限结构、完成任务过滤、偏好键和拖放保存回滚逻辑。

不重构现有单文件前端，不修改后端与状态存储模块，不增加跨设备布局同步。

## 异常处理

- 任务保存失败：恢复旧优先级并提示失败。
- 新增任务失败：保留当前象限和布局，显示现有同步错误提示。
- 本地偏好损坏：忽略损坏值并恢复默认模式和比例。
- 拖动被取消或目标无效：不修改任务。

## 验证方案

1. 扩展 UI 源码测试，覆盖模式切换、四个象限、未完成过滤、用户级偏好、中心点限制、恢复默认和优先级保存回滚。
2. 运行 `npm.cmd test`，确认现有状态看板、任务 API 和其他功能无回归。
3. 运行 `npm.cmd run build`，确认内联应用脚本可解析且生产构建成功。
4. 浏览器验证默认模式、模式记忆、中心点鼠标和键盘操作、跨象限拖卡、筛选、批量删除及窄屏布局。

## 验收标准

1. 用户首次进入部门待办看到四象限模式，可切换回列表模式且选择会被记住。
2. 四种优先级的未完成任务进入正确象限，已完成任务不在四象限出现。
3. 跨象限拖卡成功后刷新页面仍保持新分类；保存失败时任务回到原象限。
4. 中心点可在 25%–75% 范围内移动，刷新后恢复用户上次布局，恢复按钮可回到 50% × 50%。
5. 搜索、模块筛选、“只看我的”、新增任务和批量删除在四象限模式中正常工作。
6. 列表模式原有按状态分列和跨列更新状态行为不变。
