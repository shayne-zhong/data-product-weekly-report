# 部门目标预计达成与历史值恢复设计

## 目标

在部门目标中区分“预计达成”和“实际达成”：预计达成由用户手工维护并用于完成度计算，实际达成继续由已完成待办贡献数汇总。同时尽可能恢复上个版本中手工填写在 `current` 字段里的数据。

## 已选方案

采用显式字段迁移方案：新增 `expectedCurrent` 保存预计达成，保留 `current` 表示实际达成。前后端均使用稳定字段语义，不复用或交换字段含义。

## 页面行为

- 在“目标”列之后新增“预计达成”列，支持手工输入并沿用目标表自动保存。
- 原“已达成”列改名为“实际达成”，继续只读展示已完成待办贡献数。
- 完成度按“预计达成中的首个有效数字 ÷ 目标值中的首个有效数字”计算。
- 预计达成为空、无法解析或目标值无有效正数时，完成度为 0%。
- 平均完成度及没有手工状态时的自动状态判断均使用预计完成度。
- “关联待办”列保持左对齐，默认宽度由 160 调整为 120，最小宽度 100，最大宽度 180。

## 字段与数据规则

### `expectedCurrent`

- 新增的可编辑字符串字段，用于兼容带单位或说明的目标值表达，例如 `8项`。
- 用户编辑后通过现有目标保存接口持久化。
- 服务端不得用待办贡献或其他派生数据覆盖该字段。
- 新目标默认值为空。

### `current`

- 继续作为实际达成字段。
- 服务端响应时由状态为“已完成”的关联待办贡献数实时汇总。
- 前端只读，不允许用户直接修改。

## 历史值恢复

### 恢复原则

迁移前必须先导出一份线上原始状态快照，不直接在唯一线上数据上试错。恢复程序只处理尚未拥有 `expectedCurrent` 的目标，保证重复执行不会覆盖用户后来填写的预计值。

### 可恢复判定

上个版本曾将手工已达成值保存在目标 `current`。新版本在目标表发生保存时，会把 `current` 覆盖为待办贡献汇总。因此恢复必须保守：

1. 若快照中的目标记录在上次功能版本上线前最后更新，则其旧 `current` 可作为历史手工值迁入 `expectedCurrent`。
2. 若目标记录在上次功能版本上线后保存过，无法可靠区分 `current` 是历史手工值还是实际贡献值，不自动迁移。
3. 无法恢复的目标将 `expectedCurrent` 留空，完成度按 0% 计算。
4. 不使用 2026-07-22 的迁移备份覆盖当前线上全量状态；该备份只作为人工比对证据。

实现时应先从部署记录确定上次版本上线时间边界，并在迁移报告中列出“已恢复、留空、原本已有预计值”三类数量和目标 ID，供人工复核后再写入。

## 迁移流程

1. 只读导出当前线上原始状态及元数据，保存到新的时间戳备份目录。
2. 根据上线时间边界生成迁移预览，不写线上数据。
3. 输出每个目标的判定、旧 `current`、拟写入的 `expectedCurrent` 和原因。
4. 人工确认迁移预览后再执行一次写入。
5. 写入后重新读取线上状态，核对目标数量、ID、预计值及其他业务实体未发生意外变化。

## 错误与安全边界

- 无法读取线上原始状态时停止，不创建空迁移结果。
- 无法确定上线时间边界时停止自动恢复，所有缺失预计值保持为空并请求人工决定。
- 迁移预览与实际写入使用同一判定函数，避免预览和执行口径不一致。
- 任一写入或回读校验失败时报告错误，不声称恢复成功；保留迁移前快照供人工恢复。
- 不修改待办、贡献数、产物、周报、账户或其他部门数据。

## 验收标准

1. 目标表显示“预计达成”和“实际达成”，不再显示“已达成”。
2. 预计达成可编辑、可保存、刷新后保持；实际达成保持只读和现有贡献汇总逻辑。
3. 完成度、平均完成度和自动状态使用预计达成；预计达成留空时为 0%。
4. 新目标的预计达成为空。
5. 可确认未被新版本覆盖的旧 `current` 被迁入 `expectedCurrent`。
6. 无法可靠恢复的历史值保持为空，不复制当前实际达成。
7. 迁移重复执行不会覆盖已有 `expectedCurrent`。
8. “关联待办”列默认宽度 120，允许在 100 至 180 之间调整，表头和内容左对齐。

## 验证策略

- 领域/API 测试：字段持久化、实际达成派生、预计值不被覆盖、空值和非法值完成度。
- UI 合约测试：列名、列顺序、预计值可编辑、实际值只读、完成度数据源、关联待办列宽与左对齐。
- 迁移测试：可恢复、上线后已保存、已有预计值、重复运行和预览不写入。
- 手工检查：用带单位目标值验证预计完成度；刷新页面验证预计值；确认待办完成仅改变实际达成。

## 预计修改范围

- `PRD.MD`：同步字段语义、计算口径和恢复规则。
- `public/index.html`：新增列、改名、完成度数据源及关联待办列宽。
- `api/[...path].mjs` 与目标领域辅助模块：保留 `expectedCurrent`，继续派生 `current`。
- `scripts/`：新增只读预览和经确认后执行的历史值迁移工具。
- `test/*`：补充 API、UI 和迁移测试。

本变更不改变模块边界，无需更新 `PROJECT_ARCHITECTURE.md`。
