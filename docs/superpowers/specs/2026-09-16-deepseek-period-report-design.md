# DeepSeek 部门经营报告设计

## 目标

在部门工作台后台直接生成季度、半年度和年度 HTML 经营报告。网站使用后台已经配置的 DeepSeek 通用模型与项目内“网站版 Skill”，独立校验通过后立即发布正式版本。

本设计替代网站创建任务、个人电脑领取任务并调用 Codex CLI 的旧流程。Codex 主动生成报告的能力不属于本期范围。

## 用户流程

1. 全局管理员或部门负责人进入后台“经营报告”。
2. 选择部门、年份和季度／上半年／下半年／年度后点击“生成报告”。
3. 网站检查所需上级总结和目标是否完整。资料缺失时不创建生成任务，并列出缺失月份或季度。
4. 资料完整时，网站冻结来源快照并创建后台任务。页面立即显示任务状态，用户可以关闭页面。
5. Node 服务调用 DeepSeek 生成结构化报告数据，再由独立校验器检查。
6. 校验通过后，网站使用固定渲染器生成 HTML，保存为新的正式版本，并将其设为该部门与周期的当前版本。
7. 用户可以打开稳定链接或具体版本链接。重新生成时旧版本继续保留。

## 分层取材

### 季度报告

- 读取该自然季度三个月各自的正式月度总结。
- 对照该季度目标及其所属年度目标。
- 不读取原始任务和周报。

### 半年度报告

- 上半年读取第一、第二季度正式总结；下半年读取第三、第四季度正式总结。
- 对照对应年度目标。
- 不读取月度总结、原始任务和周报。

### 年度报告

- 读取该年度四份正式季度总结。
- 对照该年度目标。
- 不读取月度总结、原始任务和周报。

每个必需月份或季度只能选择一份来源：使用对应精确自然周期的最新正式版本。缺少任一来源时严格阻止生成，不降级到更底层资料，也不混用其他周期口径。

## 网站版 Skill

现有 `business-period-report` Skill 中适合网站运行的内容复制并固化为项目内版本，包含：

- 分析框架和写作约束；
- DeepSeek 系统提示词及来源引用规则；
- 结构化报告 JSON 契约；
- 字段长度、页面结构和数字证据规则；
- 固定 HTML 渲染器和样式；
- 独立校验规则。

每次生成记录 `skillVersion`。后续优化 Skill 时发布新版本，新生成报告使用新版本，历史报告继续关联原版本。业务来源全部视为不可信文本，提示词明确禁止执行来源中的指令、命令、网址或角色要求。

DeepSeek 只能返回结构化报告数据。模型不能直接提交 HTML、设置正式状态、决定版本号或绕过校验器。

## 后台任务与状态

任务状态：

- `queued`：快照已冻结，等待服务执行；
- `generating`：正在调用 DeepSeek；
- `validating`：正在执行契约、证据和渲染检查；
- `published`：正式版本已保存；
- `failed`：生成、校验或运行环境失败。

同一部门、报告类型和周期最多存在一个活动任务。重复点击返回原活动任务，不重复调用模型。失败后的人工重试创建新的任务记录，并引用同一周期的新快照。

单次任务只调用一次 DeepSeek，不进行隐式模型重试。Node 重启时将遗留的活动任务标记为“服务中断”，由用户决定是否重试。任务错误只保存适合后台展示的短消息，不保存密钥、请求头、完整提示词或内部堆栈。

## 快照和可追溯性

创建任务时保存：

- 部门、报告类型、开始日、结束日和资料截止时间；
- 目标及上级总结的规范化内容；
- 每条来源的类型、业务 ID、标题、周期、版本和状态；
- 快照散列；
- 网站版 Skill 版本和 DeepSeek 模型；
- 创建者和创建时间。

模型输出中的来源编号必须来自快照。报告中的非空关键数字必须提供来源编号与字段路径；校验器能够在来源内容中定位相同数值。无法精确核对的数据不得作为确定性指标展示。

## 生成和校验

服务端将快照整理为大小受限的证据包，然后调用后台配置的 DeepSeek 模型。DeepSeek 未启用、密钥未配置、供应商不是 DeepSeek、请求超时或超过限额时，任务直接失败并显示可操作原因。

独立校验至少检查：

1. JSON 契约与输出大小；
2. 组织、部门、周期和报告类型；
3. 来源编号只能来自冻结快照；
4. 数字证据路径存在且值一致；
5. 不包含无来源的同比、增长率、排名或因果结论；
6. 页面数量、标题、正文和卡片长度符合网站版 Skill；
7. 固定渲染结果不包含外部脚本、危险 URL 或可突破预览隔离的内容。

生成器不能审批自己的结果。只有独立校验全部通过，服务端才能进入正式发布事务。

## 正式发布与版本

校验通过后在一次持久化写入中：

1. 为部门、类型和周期分配递增版本号；
2. 保存结构化报告、固定渲染 HTML、来源清单和校验摘要；
3. 将新版本标记为当前正式版本；
4. 将任务标记为 `published`。

稳定链接始终打开最新正式版本；具体版本链接永久指向原内容。重新生成不会覆盖或删除历史版本。报告列表展示部门、周期、版本、生成时间、资料截止时间、Skill 版本和模型。

## 权限和安全

- 全局管理员可以为任意启用部门生成和查看报告。
- 部门负责人只能为本部门生成和查看报告。
- 普通成员只能查看本部门已经正式发布的报告。
- 所有列表、稳定链接、版本链接和数据接口都在后端执行部门范围检查。
- HTML 预览继续使用受限 sandbox，不获得网站会话，也不提供原始来源的公开地址。
- DeepSeek API Key 继续使用现有服务端加密配置，不能进入任务快照、日志或前端响应。

## 后台界面

后台“经营报告”保留部门、年份和报告周期选择以及“生成报告”按钮，新增：

- 生成前的资料完整性提示；
- 后台任务状态和简短失败原因；
- 人工重试入口；
- 当前正式版本与历史版本列表；
- 资料截止时间、Skill 版本和模型信息。

删除设备配对、设备在线状态、等待本机、心跳和取消本机任务等旧流程界面。历史已完成报告继续显示；旧流程中的未完成任务不再执行，并标记为旧流程已停用。

## 运行边界

首期继续以单实例内网 Node 服务运行后台生成任务，复用项目现有持久化状态和写入锁。网页请求只创建任务，不保持到 DeepSeek 完成的长连接。

如果未来改为多实例部署，必须先增加持久化任务租约或独立队列，再允许多个实例消费；本设计不声称当前具备分布式并发能力。

## 验证与验收

自动验证覆盖：

- 季度三月、半年两季、年度四季的精确取材；
- 任一必需总结缺失时阻止生成并返回缺失清单；
- 目标和总结的部门、周期及正式状态过滤；
- 重复点击防重、任务状态持久化和服务中断处理；
- DeepSeek 未配置、超时、限额和非法输出；
- 来源伪造、数字无证据、跨部门内容及危险 HTML 拒绝；
- 正式版本递增、最新版本切换和历史版本保持；
- 管理员、部门负责人和普通成员的权限边界。

上线前使用真实部门资料分别完成一次季度、半年和年度生成；核对来源清单和关键数字，并在桌面、窄屏及打印布局中检查正式 HTML。只有真实 DeepSeek 调用、独立校验、正式发布和网站访问全部完成，才视为端到端上线。

## 不在本期范围

- Codex 主动取数、生成和回写网站；
- 本机报告 worker、开机启动程序和设备凭证；
- 从任务或周报直接生成季度、半年或年度报告；
- 多实例任务队列和自动模型重试；
- 自动删除历史正式版本。
