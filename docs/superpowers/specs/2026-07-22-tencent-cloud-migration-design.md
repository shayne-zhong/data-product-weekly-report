# 腾讯云生产迁移与部署设计

## 目标

将当前 Vercel 生产环境中的部门工作台完整迁移到已绑定的腾讯云开发默认环境 `shayen-d0g1qu7hfe1045db1`，保留现有用户、部门、任务、报告、目标、设置和会话数据。部署完成后，腾讯云地址应同时提供前端页面和 `/api/*` 服务，且不再依赖 Vercel Blob 才能正常运行。

## 已确认约束

- 目标环境：CloudBase 默认环境 `shayen`，地域 `ap-shanghai`。
- 部署方式：CloudBase Run，公开 Web 访问。
- 数据来源：Vercel 项目 `deploy-weekly-report` 的生产 Blob 状态文件。
- 切换窗口：允许旧 Vercel 站点暂停写入约 5 分钟。
- 部署必须先通过安全预检、自动测试和生产构建。
- 部署后必须查询真实云端状态并访问线上地址验证。

## 方案选择

采用 CloudBase Run 与 CloudBase 数据库组合：

- CloudBase Run 在同一域名下提供静态页面与 API，避免跨域和双站点路由。
- CloudBase 数据库存储完整状态文档，避免容器临时磁盘导致数据丢失。
- Vercel 仅作为迁移数据源；切换完成后，新系统不再依赖 Vercel Blob。

未采用的方案：

- 静态托管加 HTTP 云函数：需要额外的跨域、网关和双部署配置，改动更大。
- 腾讯云运行服务继续访问 Vercel Blob：上线较快，但没有完成数据迁移，保留跨云故障点。

## 运行架构

### 生产服务

新增一个最小 Node.js 生产入口：

- 监听平台注入的 `PORT`。
- `/api/*` 请求适配并复用现有 API 处理器。
- `/admin`、`/admin/*` 和未知前端路由返回 `public/index.html`。
- 静态资源从 `public` 目录提供，并设置合理的内容类型和缓存策略。
- 提供不含敏感信息的 `/healthz` 健康检查。

服务采用无状态设计，实例内存和临时磁盘都不作为业务数据源。

### 数据存储

增加独立的状态存储适配层，保持现有 `loadState` / `saveState` 语义：

- Vercel 环境继续兼容现有 Blob 读取逻辑，便于迁移前验证。
- CloudBase 环境从服务端专用集合读取和写入单一状态文档 `state-v1`。
- 状态文档包含现有完整 JSON 结构，不在本次迁移中拆分业务表，降低数据转换风险。
- 浏览器不直接访问该集合；数据库安全规则拒绝客户端读写，只有服务端运行身份操作。
- 写入携带版本号和更新时间；迁移工具在导入前后计算 SHA-256 和记录数量摘要。

## 安全设计

- 删除 `REPORT_SYNC_KEY` 的代码默认值和部署配置中的明文值。
- 删除管理员用户名、密码的代码默认值；生产环境缺少必要变量时服务拒绝启动或管理操作拒绝访问。
- 管理员凭证、同步密钥和 AI 服务密钥仅通过 CloudBase Run 环境变量注入。
- 迁移使用的 Vercel Blob 凭证只写入被 Git 忽略的临时环境文件，完成后删除。
- 日志不得打印 Blob 凭证、密码、同步密钥、用户密码哈希或完整状态内容。
- 依赖审计发现高危漏洞、密钥扫描发现真实凭证、测试失败或生产构建失败时停止部署。

## 生产构建

新增明确的生产命令：

- `npm test`：运行全部自动测试。
- `npm run build`：校验生产入口、前端内联脚本和必要静态资源，生成可部署产物或确认源部署结构完整。
- `npm start`：以生产模式启动同域 Node 服务。

CloudBase Run 使用 Node.js 运行时，资源初始配置为 0.25 vCPU、0.5 GB 内存、最小实例数 0、最大实例数 3，并开放 Web 访问。若平台不支持该组合，则使用平台允许的最小等比例配置。

## 数据迁移流程

1. 确认 Vercel 生产部署为 READY，记录生产域名和 Blob 元数据。
2. 通过 Vercel CLI 登录并从 `deploy-weekly-report` 拉取生产环境变量到临时文件。
3. 通知进入写入冻结窗口，停止旧站业务写入。
4. 导出 `data-product-weekly-report/state-v1.json`，保存本地备份。
5. 记录源文件大小、更新时间、SHA-256，以及 users、sessions、weeks、tasks、reports、goals、departments 等数量。
6. 再次查询源 Blob 元数据；如发生变化，重新导出并重新计算摘要。
7. 在 CloudBase 创建或确认服务端状态集合和最小权限规则。
8. 将完整状态文档导入 CloudBase，读取回传并验证哈希与记录摘要。
9. 部署 CloudBase Run 服务，注入必要生产环境变量。
10. 腾讯云验证通过后结束冻结窗口；Vercel 保持可回滚状态，不立即删除数据或项目。

## 验证与验收

部署前：

- Git 工作区范围清晰，无意外未提交文件。
- 敏感文件和常见密钥模式扫描通过。
- 依赖高危漏洞审计通过。
- 全部自动测试通过。
- 生产构建与本地生产服务健康检查通过。
- Vercel 导出数据的 JSON 解析、哈希和记录摘要通过。

部署后：

- CloudBase Run 服务状态为正常，最新版本构建成功且公开地址可用。
- `/healthz` 返回成功且包含部署版本，不包含敏感配置。
- 线上首页返回 200，标题为“部门工作台”，favicon 可访问。
- 未登录访问业务 API 返回 401。
- 公开设置接口可访问且不泄露成员账号或密钥。
- 使用迁移后的既有账号登录成功，并能读取对应部门数据。
- 云端数据摘要与 Vercel 源摘要一致。
- 查询最新部署日志，不存在启动错误、数据库连接错误或连续 5xx。

## 失败处理与回滚

- 导入校验失败：不部署，保留源备份并清理未完成的目标数据。
- 构建或部署失败：查询构建日志，修复后重新部署；Vercel 继续承担生产访问。
- 线上验证失败：保持 Vercel 可用，不宣布切换完成；回退到上一 CloudBase Run 版本或停止新服务。
- 成功后暂不删除 Vercel 项目、Blob 或备份，待用户另行确认下线。

## 交付信息

最终报告包含：

- CloudBase 环境 ID、服务名和地域。
- 部署版本或构建 ID。
- 真实云端运行状态。
- 数据迁移摘要与校验结果。
- 线上访问链接和已验证的关键路径。
- Vercel 保留状态及后续下线建议。
