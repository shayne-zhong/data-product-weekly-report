# 后台管理中心交互规范

## 设计定位

- 形态：面向管理者的“运营控制台”，不是装饰性数据大屏。
- 原则：待处理事项优先、当前数据范围显性、高风险操作独立确认、每页独立保存。
- 视觉：延续现有 `#315efb` 品牌蓝，以深海军蓝职责导航、冷灰工作区和低对比边框建立可靠感。
- 密度：1440×900 为主要评审尺寸，兼容 1280×720；首版不设计移动端后台。

## 评审页面

1. 全局管理员管理概览。
2. 部门负责人管理概览。
3. 部门管理。
4. 成员管理与成员详情抽屉。
5. 角色与负责范围。
6. 工作模块。
7. 业务配置。
8. 系统与安全、操作审计。
9. 运行中心、执行记录与检查并补跑。

## 原型数据边界

原型全部使用匿名模拟数据。不得连接真实 API，不得存储真实人员、密码、密钥或执行记录，不得修改 `public/`、`api/`、`lib/` 和 `test/`。

## 角色视角

- 全局管理员：可切换全部部门或指定部门；看到全部职责域。
- 部门负责人：固定本部门；只看到本部门概览、成员、角色范围、工作模块和本部门审计。
- 普通用户与模块负责人：不进入后台，因此不在原型中提供视角切换。

## 核心交互

- 概览异常和指标卡可下钻，并继承部门、周期和状态筛选。
- 成员采用列表加右侧详情抽屉；角色变更和账号停用独立确认。
- 普通配置每页独立保存；有未保存修改时，离开页面提供保存、放弃和继续编辑。
- “检查并补跑”只处理已到期但尚未完成的内容，按钮提交期间不可重复点击。
- 原型提供正常、加载、空数据和失败四种演示状态。

## 状态矩阵

| 状态 | 呈现 | 恢复动作 |
| --- | --- | --- |
| 加载中 | 内容骨架，保留页面标题与范围 | 自动恢复或切换演示状态 |
| 空数据 | 说明为什么为空，不伪造 0% | 清除筛选或新增对象 |
| 无匹配 | 保留当前筛选标签 | 清除筛选 |
| 无权限 | 不展示对象详情 | 返回可访问页面 |
| 加载失败 | 保留页面结构和失败摘要 | 重新加载 |
| 未保存 | 页面标题显示状态点 | 保存、放弃或继续编辑 |
| 高风险确认 | 展示对象、影响和明确动作名 | 取消或确认一次 |

## 评审路径

1. 全局概览发现成员异常 → 下钻成员 → 打开详情 → 修正角色范围。
2. 运行异常 → 查看执行记录 → 检查并补跑 → 查看完成反馈。
3. 修改归档规则 → 离开页面 → 未保存确认 → 保存后返回。
4. 切换部门负责人 → 验证全局配置和运行入口不可见。

## 编码确认门

只有用户明确回复“页面与交互确认，可以进入编码计划”后，才能读取更多实现文件并创建编码实施计划。
