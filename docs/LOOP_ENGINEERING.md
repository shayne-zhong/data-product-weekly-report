# 项目循环工程说明

## 自动循环

网站自身只保留两个后台循环：周任务结转与报告自动归档。Node 常驻服务是唯一自动调度器；Vercel 只提供页面和 API，不运行后台循环。WorkBuddy 另行维护企微任务同步循环，网站只提供增量、回写和结果日志接口。

## 运行边界

- 发现：Node 启动时立即补偿检查；北京时间每日 08:00–20:00 的整点每小时再次检查。
- 执行：周结转与报告归档调用各自既有领域执行器，不由浏览器加载触发。
- 验证：领域规则只处理到期数据；周结转按“部门 + 源周 + 目标周”防重，报告归档按“部门 + 总结 + 计划归档时刻”防重。
- 持久化：执行中、成功、失败及结果摘要写入业务状态；错误仅保留截断后的可读摘要，不保存密钥、请求头或堆栈。
- 人工检查点：全局管理员可在后台查看最近执行状态并人工补跑；自动循环不得修改归档时间、强制提前归档或绕过任务完成规则。

## 限制与恢复

- 每个循环同一时刻只运行一次，失败不无限重试，等待下一小时或管理员人工补跑。
- Node 停机期间不执行任务；恢复启动后依靠补偿检查追赶漏跑。
- Vercel 不配置 Cron。若未来要启用云端调度，必须重新确认套餐、频率、鉴权和重复投递验证，再更新本说明与 PRD。

## WorkBuddy 企微同步循环

- 发现：WorkBuddy 每 5 分钟调用增量接口，以成功处理批次的最大 `updated_at` 作为持久水位。
- 交接：网站任务以 `task_id` 标识；每条企微执行结果以独立 `event_id` 标识并单条回传。
- 验证：HTTP 状态只证明接口接收；生产验收另由 WorkBuddy `--once` 冒烟、网站后台日志和真实企微待办共同判定，生成方不能自行批准结果。
- 持久化：WorkBuddy 保存水位、待回传队列及失败记录；网站保存脱敏、幂等的结果日志和运行概览。
- 调度：任务发现每 5 分钟一次；结果回传仅在 5xx 或网络失败时按 5 秒、30 秒、120 秒重试，最多 3 次，且复用原 `event_id`。
- 人工检查点：Token 轮换、userid 映射冲突、生产部署、422 完成拒绝和三次回传失败必须由人员处理。
- 网络边界：本期不开放 3902 端口、不监听出站 webhook，结果回传失败不得中断任务同步主链路。

## 部门 HTML 经营报告

- 发现：仅由后台管理员或本部门负责人手动创建季度、半年度、年度任务；本机轮询只领取已创建任务，不自行创建报告。
- 交接：网站冻结部门资料快照，生成任务 ID、版本和快照散列。本机每份任务独立目录，单机串行；凭证只能访问绑定部门的报告执行接口。
- 运行：首期要求单实例 Node 网站入口，沿用项目进程内写锁和持久化状态；Vercel 多实例不提供安全领取保证，因此拒绝创建／领取，不伪称支持分布式互斥。
- 校验：采用报告 Skill 的固定渲染模块；服务端复核契约、部门、周期、来源及数字证据；本机浏览器逐页检查桌面、窄屏、打印和翻页。模型不能设置完成状态或自行上传任意 HTML。
- 人工边界：按用户确认，技术校验通过的报告自动集成网站，不增加手工上传步骤。HTML 保留 Skill 的草稿标识；自动完成不代表业务口径、因果结论已人工批准。
- 持久化：任务、快照、执行归属、心跳、报告数据、校验记录与版本保存在网站既有持久化状态。HTML 由网站固定渲染模块从已保存数据生成，不依赖本机存活。本机产物和回传进度保存在用户应用数据目录，不写入全局 Skill。
- 预算：单任务生成上限 20 分钟，最多一次带校验错误的修复；输出数据不超过 512 KB，快照不超过 2 MB；不自动重复生成失联任务。网络回传有限重试，仍失败保留待回传记录，后续轮询继续回传。
- 恢复：心跳超过 90 秒显示本机连接中断，原执行归属在总时限内保留，防止另一执行重复花费额度。总时限到期记失败；重试新建版本，旧执行无权覆盖。取消后结果拒绝入库。
- 权限：管理员可跨部门创建／查看，部门负责人仅本部门创建，普通用户仅查看本部门已完成报告。列表、稳定链接、单版本及数据下载均在后端鉴权。HTML 使用不含 allow-same-origin 的 sandbox。
- 配置：一次性下载绑定凭证，只保存本机私有配置，不放入网址、日志或仓库；支持后台停用执行设备。连接生产、发布和开机启动仅在目标与授权落实后执行。
- 验证：独立 API 测试覆盖来源隔离、重复任务、领取互斥、超时、取消、旧执行回传、数字拒绝与历史版本；运行本机执行程序和真实浏览器验证完整链路。
